# FSM Panel Open

Открытая исследовательская версия восстановления FSM_PANEL 3.1.2.
**Полная замена оригинала пока не готова.** Реальные игровые сценарии остаются
недоступными до завершения анализа и стендовой проверки. Симулятор помечен явно.

## Запуск из исходников

Требуются Windows x64, Python 3.14.6, uv, Node 24.19.0 и pnpm 11.25.0.
Установка не изменяет оригинальную поставку.

```powershell
uv sync --frozen --group dev
pnpm --dir worker install --frozen-lockfile
pnpm --dir worker build
uv run python -m fsm_panel --simulate
```

Симулятор не запускает Steam/CS2 и не отправляет обмены. В нём можно добавить тестовые
аккаунты, запустить/приостановить/остановить их и проверить журнал. Данные симулятора
отделены от production. Импортированные секреты в обоих режимах защищаются Windows DPAPI.
Приватные настройки хранятся в `settings.vault.json`, исходный JSON импортируется отдельно.

```powershell
uv run python -m fsm_panel
```

Реальный режим без активированного онлайн-допуска блокирует новые операции. Даже с
лицензией неподтверждённый GameAdapter сообщает о недоступности, а не изображает успех.
DPAPI защищает импортируемые пароли в текущем Windows-профиле.

## Видео-конфиг и BES

На вкладке «Видео-конфиг» выберите рабочую копию шаблона и Steam-конфиг,
просмотрите изменения и примените их с резервной копией. По умолчанию меняются
только VendorID/DeviceID; точная старая глобальная замена включается отдельно.
Есть CLI для автоматизированной подготовки: [контракт и команды](docs/video.md).

Вкладка «Ограничение CPU» работает только с процессами, зарегистрированными панелью,
и проверенным BES 1.7.9. Обычный симулятор не выполняет ограничение. Адаптер и
журнал восстановления готовы, но GUI пока не создаёт реальные игровые процессы;
подключение к игровому запуску и проверка фактического CPU остаются следующими
этапами. [Контракт BES](docs/bes.md) описывает эти ограничения.

Подготовка userdata и autoexec доступна на вкладке «Конфиги игры» и через
[CLI конфигов](docs/config-tools.md): предпросмотр, проверка отпечатка, запись с
резервной копией. [Планировщик запуска](docs/launch-plan.md) вычисляет аргументы,
окружение и файловые предложения без запуска Steam и изменений реестра.

На вкладке «GSI-конфиг» можно подготовить конфиг телеметрии в той же рабочей копии:
порт, индекс файла и собственный токен из отдельного файла. Предпросмотр и запись
доступны также через CLI. [Контракт GSI-конфига](docs/gsi-config.md) описывает
резервное копирование и защиту от изменений после предпросмотра.

Вкладка «Уведомления» предоставляет ручные команды Telegram: текст, фото и
редактирование по ID. Требуется действующий допуск; в симуляторе отправка отключена.
Неопределённый результат не повторяется автоматически. Сетевой контракт пока
проверен только подставным транспортом: [возможности и ограничения](docs/telegram.md).

Там же можно [собрать изображение двух предметов](docs/item-composite.md) из локальных
PNG/JPEG и сохранить новый PNG. Подготовка работает без лицензии и в симуляторе;
сохранение изображения само по себе не отправляет сообщение.

Для исследования копий консольных логов есть [API поиска файлов](docs/console-logs.md).
Он читает метаданные в выбранных каталогах и сообщает о неполном обходе; игровые
действия по этим результатам пока не запускаются. Во вкладке **«Журнал → Копия
игрового лога»** можно [прочитать выбранную локальную копию](docs/console-parser.md)
и увидеть извлечённые значения и ошибки. Год записей задаётся явно; чтение доступно
без лицензии и не меняет состояние аккаунтов.

## Лицензирование

См. `docs/licensing.md` для сервера, выдачи ключа и CLI. Оплата полностью выполняется
внешним приложением. Его интеграция меняет права доступа через отдельный серверный API.

Клиентский JSON содержит доверенную конфигурацию, но не ключ активации:

```json
{
  "base_url": "https://licenses.example.invalid",
  "issuer": "fsm-license",
  "audience": "fsm-panel",
  "public_keys": {"production-key-id": "BASE64URL_PUBLIC_KEY_FROM_YOUR_SERVER"}
}
```

```powershell
uv run python -m fsm_panel --license-config C:\secure-config\license-client.json
```

После запуска введите ключ активации на вкладке «Лицензия». Сервер и ключи проверки
задаются доверенной конфигурацией; клиент не получает право доверять любому ключу из сети.
Точные issuer/audience/key-id должны совпадать с конфигурацией сервера.

## Проверки

```powershell
uv run ruff check src tests scripts
uv run mypy src
pnpm --dir worker typecheck
pnpm --dir worker test
$env:QT_QPA_PLATFORM = 'offscreen'
uv run pytest -m "not stand and not postgres"
uv run python -m fsm_panel --simulate --smoke-test --data-dir .\test-results\fresh-smoke-data
```

Настоящие PostgreSQL-тесты требуют `FSM_TEST_POSTGRES_URL`. CI содержит отдельный job
с PostgreSQL; локальный пропуск этих тестов не подтверждает корректность гонок на сервере.
50 клиентов в симуляторе не заменяют 50 реальных клиентов на стенде.
Для каждого `--smoke-test` выбирайте новый пустой каталог данных; проверка создаёт
синтетическую запись и подтверждает штатную остановку GUI/worker.

## Сборка

Зафиксируйте проверенные изменения в Git перед сборкой: вместе с EXE создаётся
`dist/FSMPanelOpen-source.zip` с исходниками того же commit. Нужен чистый checkout.

```powershell
uv run python scripts/build_desktop.py --research-build
uv run python scripts/verify_desktop.py dist/FSMPanelOpen/FSMPanelOpen.exe --output test-results/packaged-smoke.json
```

Результат: `dist/FSMPanelOpen/FSMPanelOpen.exe`. Это исследовательская сборка; актуальные
ограничения поставляются вместе с ней. Запуск `--simulate` выбирается явно.
