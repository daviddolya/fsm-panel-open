# FSM_PANEL: план исследования и переписывания силами ИИ-агентов

Дата утверждения: 13 октября 2026 года. Исполнение начато по прямому запросу владельца.
Рабочий репозиторий: `fsm-panel-open`. Исходная поставка: `FSM_PANEL v.3.1.2`.
Результаты исполнения и реальные ограничения ведутся отдельно в `fsm-panel-open/docs/STATUS.md`.

## 1. Цель и решения

Создать открытое Windows-приложение, сохраняющее весь подтверждённый рабочий функционал FSM_PANEL 3.1.2, с поддержкой до 50 клиентов. Интерфейс и внутреннюю архитектуру разрешено улучшать. Разработка — ИИ-командой Codex, приоритет качества, проверка на отдельном Windows-стенде.

Оригинал заблокирован лицензией. Новая система лицензирования: срок действия + лимит компьютеров, постоянный онлайн. Оплата полностью находится во внешнем приложении. В панели нет платёжных SDK, покупки или оформления подписок.

Собственный код — GPL-3.0-only; сторонние лицензии проверяются отдельно. Разработка в отдельном Git-репозитории. Оригинальные файлы неизменяемы. Каждая функция должна иметь спецификацию, реализацию, автоматический тест и результат стенда. Моки не доказывают паритет.

## 3. Целевая архитектура

Python3.14, PySide6/Qt Widgets; типизированное asyncio-ядро; pywin32/psutil адаптеры; Node24 LTS/TypeScript worker; SQLite журнал и состояние; JSON импорт/экспорт; DPAPI секреты. Сервер: FastAPI/PostgreSQL/Alembic. Тесты: pytest/pytest-qt/Hypothesis/Vitest. PyInstaller onedir со встроенным Node, запуск также из исходников. Версии закрепляются lock-файлами.

Паттерны новой версии: ports/adapters, state machine, очередь на аккаунт, command/event, repositories, dependency injection, журнал внешних операций. Это проектные решения, а не приписываемые оригиналу свойства.

Интерфейсы: AccountRepository, WorkflowCoordinator, ProcessController, WindowController, GameAdapter, SteamTradeService, NotificationService, LicenseClient, Clock. Qt GUI только в главном потоке; asyncio координатор отдельно, обмен командами/сигналами. IPC Python/Node — приватные stdin/stdout JSON Lines с version/request_id; диагностический stderr без секретов.

Состояния trade: not_sent, created_pending_confirmation, confirmed, sent, failed, unknown_outcome. При неизвестном результате сверка обязательна до повтора. Импорт всех49 ключей сохраняет неизвестные поля. Значения поставки не объявляются defaults. Sandbox/no-sandbox реализуются после подтверждения. BES — отдельный версионированный адаптер. Изменения библиотек — явные patches. Миграции с резервной копией и откатом. Исправления дефектов документируются отдельно. Elevation только по доказанной необходимости.

### Лицензирование

Внешняя система передаёт external_customer_id, external_entitlement_id, expires_at, device_limit, status, revision. Платёжные данные не передаются панели.

API:
- PUT /internal/v1/entitlements/{external_id}: серверная выдача/продление/отзыв.
- POST /v1/activations: активация устройства.
- POST /v1/leases/renew: обновление онлайн-допуска.
- DELETE /v1/activations/{id}: освобождение устройства.
- GET /v1/license/current: состояние лицензии.

Отдельная сервисная авторизация; идемпотентность; устаревшие revision не меняют новое состояние. PostgreSQL транзакционно проверяет лимит. Установочный ID и ключевая пара устройства, private key через DPAPI. Подписанный допуск максимум60секунд, обновление каждые30; expiry ограничен лицензией. Без допуска новые операции запрещены, текущие безопасно останавливаются. Stop/export/reconciliation доступны всегда. Монотонные часы для интервалов, время лицензии серверное. Перенос через административный API/CLI; кабинета и оплаты в v1 нет. Открытый клиент модифицируем: серверная проверка не гарантирует невозможность обхода локального кода.

### 2 — Ядро/лицензии (A0/A3/A7/A8)
