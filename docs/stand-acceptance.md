# Последующая проверка на Windows-стенде

На этой итерации владелец поручил работать только с локальной поставкой. Доступа
к отдельному стенду нет. Ни один пункт ниже не объявлен пройденным.

## Подготовка

1. Выделить Windows x64-машину; записать версию ОС, CPU, RAM, GPU, драйверы,
   свободное место, версии Steam/CS2, Node и сборок обеих панелей.
2. Использовать тестовые аккаунты и тестовые предметы. Подготовить действующую
   лицензию оригинала, если доступна; иначе пометить сравнение оригинала blocked.
3. Скопировать поставку и данные в отдельные каталоги. Снять резервные копии
   settings, Steam userdata/config, maFiles, sessions и локальной БД новой панели.
   Не отправлять реальные секреты в Git, отчёты, скриншоты и промпты.
4. Выполнить чистую установку по README и `docs/licensing.md`; отдельно проверить
   HTTPS и доверенные ключи. Исследовательская сборка пока не является релизом.

## Карточка каждого сценария

Для записи использовать `contracts/stand-observation.schema.json`. Запись должна
содержать feature_id из матрицы, SHA-256 сборки, условия, шаги, ожидаемый и фактический
результат, измерения и относительные пути обезличенных доказательств. Статус
`passed` допустим только после выполнения; `blocked` и `not_run` успехом не считаются.

| Сценарий | Проверяемое поведение | Минимальные ошибки |
| --- | --- | --- |
| Импорт настроек и аккаунтов | 49 ключей, неизвестные поля, UTF-8, DPAPI и повторный запуск | Повреждённый JSON, дубликаты, потеря доступа к DPAPI |
| Видео-конфиг | GPU ID, выбранная копия шаблона, эффект safe/legacy, резервная копия | Изменение файла после предпросмотра, ACL, блокировка записи, восстановление |
| Конфиги аккаунта и autoexec | Принятие восстановленных VDF/VCFG реальными Steam/CS2, сохранение чужих настроек, ветви overlay/localconfig | Права на файлы, блокировка живым процессом, кодировка, сбой между переименованиями и откат |
| GSI-конфиг и приёмник | Фактический адрес listener, индекс файла, регистрация каждого аккаунта и новый токен, набор полей | Занятый порт, старый индекс, неверный токен, несколько клиентов одной установки, потеря listener |
| BES | Совпадение исходников/бинарника, фактическая доля CPU, восстановление потоков, адресные stop/exit | Падение панели/BES, отказ Native probe, PID/TID/HWND reuse, чужой экземпляр BES, потеря лицензии |
| Запуск Steam/CS2 | Окончательные аргументы, процессы, окна, журнал и отмена | Плохой путь, недостаточные права, окно входа, timeout, PID reuse |
| Оба режима запуска | Sandbox / без sandbox, профиль и каталоги кэша | Отсутствие sandbox, занятый порт, повреждённый loginusers.vdf |
| Лобби и поиск | По кодам / списку друзей, состав партий, приём приглашений | Недоступный аккаунт, повторный invite, потерянное окно |
| Автоaccept / anti-AFK | Подтверждённые триггеры, интервалы, остановка | Ложный визуальный триггер, изменение DPI, потеря фокуса |
| Партии и переподключения | Таймер, shuffle, drop/armory, остановка | Сбой одного клиента, потеря GSI, позднее событие |
| Инвентарь и обмены | Несколько инвентарей, выбранные предметы, pending/sent | Частичный отказ, потеря ответа, повтор webSession |
| Восстановление обмена | Сверка известного offer_id; неизвестный исход не отправляется повторно | Перезапуск worker/панели в момент отправки |
| Уведомления | Установленные текстовые/графические сценарии | Сервис недоступен, 429, повторная доставка |
| Лицензия | Активация, срок, лимит ПК, отзыв, перенос | Потеря сервера, подмена подписи, откат часов, гонка активаций |
| Сборка | Чистая машина без Python/Node, пути с Unicode и пробелами | Отсутствующие DLL/runtime, восстановление резервной копии |

Не выполнять недокументированную запись в реестр или конфиги только по наличию строки
в бинарнике. Для GAME.* сначала завершить спецификацию и реализовать адаптер; нынешний
NativeGameUnavailable намеренно сообщает об отсутствии подтверждённого поведения.

## Уточнения для восстановленных input- и Telegram-контрактов

Генераторы `input_plan` и `autoaccept_plan` пока не подключены к реальному вводу.
Следующие проверки выполняются после появления адаптера с проверкой владельца
окна и управляемой отменой. Старые ошибки очистки описаны в трассах, но не являются
требованием повторить зависшую клавишу или блокировку ввода в новом приложении.

| Контракт | Что сравнить с оригиналом и записать отдельно |
| --- | --- |
| Обычный autoaccept | Начальную задержку, четыре возможные серии, интервалы 4 с, границы `row[6] > start`, пороги 6/2, отмену перед серией и короткое замыкание после проверки количества |
| Co-op | Получение accept до проверки настроек, точное равенство набора серверов, позднее выключение ENABLE_AUTOACCEPT, сохранение принятого сервера при ошибке запуска input-задачи |
| Фоновые клики | Реальную интерпретацию `None` в wParam pywin32, координаты двух режимов, дубликаты/чужие окна и изменение заголовка; только принадлежащие новой панели окна допускаются новым адаптером |
| Пиксельный путь | DPI и геометрию, строгое `green > 88`, таймаут 7 с и старый клик после таймаута, первое доступное окно, потерю фокуса между чтением геометрии и кликом |
| Отмена ввода | Освобождение удержанной клавиши/кнопки и блокировки при исключении, отзыве лицензии и остановке; отличие от старого поведения указывать явно |
| Дополнительный anti-AFK | Порядок активации, удержаний и случайных интервалов, позднее чтение мощности; период запуска ещё требует исследования |
| Telegram вручную | Текст, фото, edit text/caption, topic, явный HTTP(S)-прокси, возвращённый message_id, отмену до и после подтверждённого ответа |
| Неизвестный исход Telegram | Потерянный ответ после отправки не вызывает автоматический повтор; оператор сверяет сообщение в тестовом чате перед ручной повторной отправкой |

Автоматическая рассылка, команды бота и графические уведомления о предметах
не подтверждаются прохождением ручных команд. Для них нужны отдельные сценарии.

## Нагрузка и длительность

- Последовательно 1 → 10 → 25 → 50 реальных клиентов; каждый переход после проверки
  остановки и восстановления предыдущей ступени.
- 24 часа на целевой ступени со сменой партий и временными разрывами связи.
- Измерять CPU/RAM/handles, число дочерних процессов, очередь задач, задержку приёма
  команды «Стоп» (≤1 с). Время завершения внешних процессов записывать отдельно.
- Повторить на оригинале с теми же условиями, если он доступен. Измерения симулятора
  из `test-results/simulator-load.json` не заменяют эти результаты.
- Любая двойная отправка обмена, потеря состояния, неконтролируемый процесс или
  неограниченный рост задач блокирует выпуск.

## Решение о выпуске

Заполнить матрицу и независимый отчёт A8. Закрыть пробелы native-спецификации,
устранить либо формально принять конкретные зависимостные риски, проверить лицензии
и состав сборки. Непроверенные функции должны быть перечислены по ID; общего
утверждения «полный аналог» до этого быть не должно.
