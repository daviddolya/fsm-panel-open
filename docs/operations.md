# Работа, резервные копии и восстановление

## Исследовательский клиент

Из исходников: `uv run python -m fsm_panel --simulate`. Из папки сборки:
`FSMPanelOpen.exe --simulate`. Режим обозначен жёлтой полосой; он не вызывает Steam.
«Добавить тестовый аккаунт» создаёт синтетическую запись. Выделите строки для запуска,
паузы, продолжения и остановки. Вкладка предметов проверяет обмены через локальный
Node-симулятор. Новый запрос сверки привязан к аккаунту последнего обмена.

Обычный запуск без `--simulate` выбирает реальные данные и требует онлайн-лицензию.
Сейчас GameAdapter намеренно возвращает `native_behavior_unverified`; лицензия
сама по себе не делает неподтверждённые игровые функции доступными.

По умолчанию данные расположены в `%LOCALAPPDATA%\FSMPanelOpen\simulation` или
`%LOCALAPPDATA%\FSMPanelOpen\production`. Для изолированной проверки задавайте
`--data-dir` с отдельным абсолютным путём. Не направляйте его в оригинальную поставку.

## Импорт и экспорт

Новый импорт аккаунтов принимает строки `login:password` либо CSV с полями
`login,password` и необязательным `display_name`. Это новый документированный формат,
а не доказанный формат всех старых maFiles/session. Реальные секреты вводятся только
локально; пароли сохраняются DPAPI. Оригинальные pickle-файлы не исполняются.

Во вкладке настроек импортируйте копию старого JSON, затем сохраните его в новый
vault. Все 49 обнаруженных ключей имеют строгие типы; неизвестные поля сохраняются.
Значения новой формы — новые безопасные значения, не восстановленные defaults оригинала.
Экспорт формы удаляет известные секреты; перед передачей отчёта проверьте также
неизвестные пользовательские поля и пути, которые могут содержать личные сведения.

## Резервная копия и откат

Конфиги userdata и autoexec готовятся отдельно от живого Steam по
`docs/config-tools.md`. Сохраните fingerprint предпросмотра; изменение исходников
или рабочей копии требует повторного просмотра. Результат применения сообщает
путь резервной копии целого изменённого дерева. При `config_rollback_failed`
сохраните backup/staging и проверьте существующую цель перед восстановлением;
не повторяйте запись поверх неизвестного результата.

Видео-конфиг готовится на отдельной вкладке. Сначала скопируйте шаблон из оригинала
в рабочий каталог, затем выберите его и существующий Steam-конфиг. «Предпросмотр»
ничего не меняет; «Применить» создаёт соседнюю `.bak` и обновляет только шаблон.
При `video_preview_stale` повторите предпросмотр. При `video_rollback_failed`
сохраните указанную резервную копию и проверьте текущий файл до новой записи.

Ограничение CPU использует отдельную рабочую копию BES 1.7.9. В симуляторе новые
ограничения отключены. Реальный игровой адаптер пока не создаёт цели для этой
вкладки. При ошибке очистки используйте «Завершить все собственные сессии BES»;
повторная попытка доступна без лицензии, в том числе после неудачного восстановления
при старте. Не удаляйте `bes.sqlite` ради снятия ошибки: это журнал владения,
который нужен для адресного восстановления. Отправленная команда ещё не означает
измеренное снижение CPU; реальные эффекты проверяются отдельно на стенде.

1. Остановите сценарии и штатно закройте клиент; дождитесь завершения процесса.
2. Скопируйте весь каталог данных, включая SQLite, `secrets`, vault, его `.bak`,
   device-файл, `bes.sqlite` и журнал worker. Не копируйте только основной SQLite при работающем WAL.
3. Держите копию в защищённом месте. DPAPI привязан к Windows-пользователю: копия
   зашифрованных файлов сама по себе не переносит секреты на другую машину.
4. Перед обновлением сохраните также папку предыдущей сборки и её manifest.
5. Для отката закройте новую сборку и восстановите **целую согласованную копию**
   каталога данных вместе с предыдущей сборкой. Не понижайте отдельные таблицы вручную.

При запуске ядро восстанавливает журнал и проверяет владение процессами по PID,
времени создания и исполняемому файлу. Неизвестный PID не становится разрешением
убить чужой процесс. Ошибка очистки блокирует новый запуск до исправления и повторной
остановки/восстановления. Повреждённая/чужая схема БД отклоняется до миграции.

## Неопределённый исход обмена

После потерянного ответа состояние `unknown_outcome` означает необходимость сверки.
Не удаляйте журнал и не создавайте новый UUID ради повтора. Если известен `offer_id`,
проверяется этот обмен. При неизвестном ID автоматическая новая отправка запрещена;
стендовый оператор сначала устанавливает результат на стороне Steam.
Завершение уже созданного обмена разрешено после истечения допуска; создание нового — нет.

## Сервер и диагностика

Конфигурация и выдача прав описаны в `docs/licensing.md`. Используйте отдельные
ключи/БД для стенда и эксплуатации; ключ подписи и service token не входят в клиент.
Резервные копии PostgreSQL выполняются стандартным `pg_dump` и восстанавливаются
в отдельную проверочную БД перед переключением. Сохраняйте ключи сервера отдельно.

Для отчёта достаточно версии сборки, стабильного кода ошибки, времени, feature_id,
обезличенного журнала и шагов воспроизведения. Не присылайте `.env`, DPAPI-файлы,
токены, cookies, maFiles, приватные дампы исследования или реальные команды входа.
Матрица и `docs/stand-acceptance.md` определяют, какие сценарии ещё нельзя принять.
