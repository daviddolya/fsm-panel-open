# Передача следующей команде

## Начало работы

Публичный репозиторий: <https://github.com/daviddolya/fsm-panel-open>.

```powershell
git clone https://github.com/daviddolya/fsm-panel-open.git
cd fsm-panel-open
uv sync --frozen --group dev
pnpm --dir worker install --frozen-lockfile
pnpm --dir worker build
uv run python -m fsm_panel --simulate
```

Нужны Windows x64, Python 3.14.6, uv, Node 24.19.0 и pnpm 11.25.0.
Начните с [состояния проекта](STATUS.md), [результатов проверок](VERIFICATION.md)
и [плана](../FSM_PANEL_REBUILD_PLAN.md). Работает исследовательская версия с
симулятором. Реальные игровые сценарии и полный паритет с оригиналом ещё не готовы.
Настройки десяти агентов находятся в `.codex/agents`; правила — в `AGENTS.md`.

Актуальные локальные числа и границы проверок записаны в `docs/VERIFICATION.md`.
Результат удалённого CI смотрите во вкладке
[Actions](https://github.com/daviddolya/fsm-panel-open/actions/workflows/checks.yml).
Локальные результаты не заменяют результат нового запуска CI.

## Передаваемые материалы

| Материалы | Где находятся |
| --- | --- |
| Собственные исходники, история `main`, тесты, lock-файлы, инструкции агентов | Публичный GitHub-репозиторий |
| Обезличенные результаты исследования и проверяемые адреса/хеши | Каталог `research` в Git |
| Оригинальная поставка, полный native-анализ, промежуточные проекты Ghidra и частные отчёты | Отдельный локальный архив владельца `handoff-private/FSMPanelOpen-private-handoff.zip` рядом с репозиторием |
| Все локальные ветки агентов | `fsm-panel-open-all-refs.bundle` внутри частного архива |
| Проверенная Windows-сборка, соответствующий исходный архив и отчёты | `fsm-panel-open/dist/FSMPanelOpen-research.zip` внутри частного архива |
| Установленные Ghidra/JDK/REA и кэши | Сохранены на машине владельца; версии и хеши указаны в `research/toolchain-manifest.json` |

Частный архив передаётся коллеге отдельно. Он не зашифрован и содержит чувствительные
исследовательские материалы. Не прикрепляйте его к публичным Issues, Releases или
промптам. Его `MANIFEST.json` содержит пути, размеры и SHA-256 включённых файлов.
Исходные каталоги владельца сохраняются на месте.

Для обычной разработки достаточно GitHub. Для продолжения native-исследования получите
частный архив у владельца, распакуйте его в отдельный рабочий каталог и прочитайте
`HANDOFF_PRIVATE.md`. Локальные пути REA/Ghidra/JDK потребуется настроить заново.
Архив Git восстанавливает исходники и ветки независимо от GitHub:

```powershell
git clone .\fsm-panel-open-all-refs.bundle .\fsm-panel-recovered
```

Исторические ветки агентов служат дополнительным контекстом; продолжайте разработку от
актуального `main`. Если при переносе используются DPAPI-файлы, они привязаны к исходному
Windows-профилю: перенос файла сам по себе не переносит возможность расшифровки.

## Устройство репозитория

| Каталог | Ответственность |
| --- | --- |
| `src/fsm_panel/core` | Состояния, очередь, репозиторий, настройки, восстановление |
| `src/fsm_panel/adapters` | Windows, процессы, DPAPI, симуляторы |
| `src/fsm_panel/ui` | Qt-виджеты и мост в отдельный asyncio-поток |
| `src/fsm_panel/trading`, `worker` | Python/Node IPC, durable операции и Steam SDK |
| `src/fsm_panel/gsi` | Аутентифицированный локальный приём телеметрии |
| `src/fsm_panel/licensing`, `src/fsm_license` | Клиент допуска и самостоятельный сервер |
| `contracts` | Версионные схемы IPC, OpenAPI, наблюдения стенда |
| `research` | Переносимые обезличенные доказательства; не исходники оригинала |
| `.codex/agents` | 10 ролей и промптов; одновременно координатор и до 3 специалистов |

Стек и реальные версии закреплены в `.python-version`, `uv.lock`,
`worker/pnpm-lock.yaml`, `worker/package.json`. Сначала выполняется `uv sync --frozen
--group dev`, затем `pnpm --dir worker install --frozen-lockfile` и `pnpm --dir worker build`.
Основные команды тестов приведены в README и CI. PostgreSQL-тесты используют отдельную
одноразовую БД из `FSM_TEST_POSTGRES_URL` и могут очищать её таблицы.

## Порядок следующей работы

1. Читать `docs/STATUS.md`, `docs/feature-matrix.json`, `research/STATIC_FINDINGS.md`
   и независимый `docs/qa-review.md` перед изменениями.
2. Выбрать одну функцию, завершить её исходную спецификацию с адресами/наблюдениями.
   Статическая ссылка на настройку не устанавливает её полный алгоритм.
3. Согласовать контракт через A0 и добавить независимый проверяемый сценарий.
4. Назначить одному агенту владение кодом, другому — проверку. Использовать ветки и
   worktree. Активной REA-сессией владеет один исследователь.
5. Менять ядро и адаптер отдельно; затем подключать вертикальный сценарий GUI.
   Не заменять `NativeGameUnavailable` на неподтверждённый успешный результат.
6. Обновить генератор/матрицу, документацию и стендовые критерии вместе с кодом.

Новые локальные срезы: `adapters/video.py` и вкладка/CLI подготовки видео;
`adapters/bes.py`, `cpu.py` и вкладка CPU; `adapters/launch_plan.py` с чистыми
планами аргументов, профиля/шейдеров и loginusers. Последний модуль не выполняет
план. `adapters/account_config.py`, `adapters/autoexec.py` и `config_cli.py`
готовят файлы только в помеченной рабочей копии; точные старые ветви и новые
транзакционные ограничения описаны в `docs/account-config.md`.
`adapters/gsi_config.py` и вкладка «GSI-конфиг» готовят конфиг телеметрии
в той же копии; `docs/gsi-config.md` фиксирует шаблон, выбор порта и границы проверки.
Следующее подключение игрового запуска должно учитывать gating/locks, вход,
окна, выбор GSI-порта и восстановление.
Адреса и отличия от оригинала приведены в соответствующих docs; независимые
проверки этой волны — `docs/offline-qa.md`. Ветка `main` содержит принятые изменения.

REA и локальные пути Ghidra/JDK задаются вне переносимого репозитория. Полный
автоанализ с 2 GiB heap ранее завершился OOM; повтор без изменения условий бессмысленен.
Используйте подготовленный частичный native-проект и ограниченные функции. Приватные
данные лежат вне Git в соседнем `research-private`; каталог содержит чувствительные
материалы и не должен попадать в релиз или автоматически прикрепляться к промптам.

## Поставка и воспроизводимость

`scripts/build_desktop.py --research-build` собирает onedir и включает runtime Node,
worker, уведомления о лицензиях и явный статус исследования. Lock-файлы фиксируют
входы сборки; побитовая идентичность двух PE-сборок не заявляется. Метаданные сборки
содержат версии инструментов, commit и хеши файлов для проверки конкретной поставки.

Перед выпуском устранить или отдельно оценить зависимости из `worker/audit`.
Не применяйте `audit fix`/слепые overrides: изменения Steam SDK требуют характеристических
и стендовых проверок. Собственный GPL-код не отменяет лицензии и условия компонентов.
